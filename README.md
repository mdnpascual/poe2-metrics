# PoE2 Metrics

**🔗 Live demo: https://d3td125rith00z.cloudfront.net**

An interactive analytics explorer for **Path of Exile 2** character builds. It aggregates
equipment, modifiers, skills, and defensive stats across thousands of high-level characters
and presents the results as cascading filters, charts, and drill-down tables — so you can see
what the meta is actually running, which affixes dominate a given slot, and how builds are put
together.

The goal is simple: turn a large pile of raw character data into fast, filterable, visual
answers to questions like *"what base types are most common on rare amulets?"*, *"which
explicit mods show up most on rings for a given class?"*, or *"what does the life/ES/armour
distribution look like across the current league?"*

> This project is read-only analytics. It exposes **only aggregated counts and percentages** —
> no character names, account names, or other personally identifying information are stored in
> the API responses or surfaced in the UI.

## How data is collected and ingested

Data collection and analytics are intentionally decoupled:

1. **Collection** — character build data is gathered externally as JSON (one file per character
   profile), each containing the character's items with full modifier data, skills, defensive
   stats, keystones, and flask setup. Collection runs on its own; this repo does not perform it
   at runtime.
2. **Ingestion** — `server/ingestv2.ts` parses those JSON files in parallel (8 worker threads)
   and batch-inserts them into a local **DuckDB** database (`explorer_v2.duckdb`). A full run
   processes thousands of characters and tens of thousands of items in ~20 seconds. Ingestion
   does a full replace on each run.
3. **Serving** — an Apollo GraphQL server queries DuckDB in-process (columnar aggregation is
   fast for `GROUP BY` / `COUNT` over the full dataset) and the React frontend renders the
   results.

```
 JSON profiles ──► ingestv2.ts (parse + batch insert) ──► DuckDB ──► GraphQL API ──► React UI
```

The DuckDB file itself is **not** committed (it is large and regenerated by ingestion).

## Features

Features are organized around the GraphQL queries that power them. All queries accept filter
inputs and are **cascading** — selecting a value in one filter narrows the available options
and counts everywhere else.

### Filtering (`filterOptions`)

A sidebar of 9 filter groups driven by live, filter-aware counts:

- **Class** — ascendancy classes
- **Slot** — equipment slots (weapon, armour pieces, rings, amulet, belt, flask, passive jewels, etc.)
- **Rarity** — Rare / Unique / Magic
- **Base Requirements** — attribute requirement type (str, dex, int and their combinations)
- **Unique Items** — appears when the Unique rarity is selected
- **Anoints** — allocated passives applied via amulet anoints
- **Keystones** — multi-select with AND logic
- **Base Type** — searchable, non-self-filtering
- Every group has search and "select all"; totals, latest-data timestamp, and league are exposed alongside the options.

### Items analytics (`itemAggregations`)

Aggregate item statistics for the current filter, rendered as charts and a sortable table:

- Distribution **by base type** and **by item name** (bar charts, click a bar to filter)
- Distribution **by rarity** and **by requirement type** (pie charts)
- **Mod frequency** breakdowns, each as its own collapsible chart:
  - Explicit mods (merged from explicit/fractured/crafted sources, deduped)
  - Implicit mods
  - Rune mods
  - Anoints (clicking opens the corresponding passive reference page)
- Average item level, corrupted count, and fractured count
- A sortable base-types table at the bottom

### Crafting Advisor & affix co-occurrence (`itemMods`)

Returns the raw per-item modifier sets (explicit, fractured, crafted, desecrated, enchant,
implicit, rune) for items matching the current filter, enabling client-side analysis:

- Explore which affixes **appear together** on the same item
- Build up a set of desired affixes and **open a matching Path of Exile 2 trade search** in a
  new tab (rarity is inferred from how many affixes are selected; base type is included when
  exactly one is selected)

### Skills analytics (`skillAggregations`)

Aggregate skill usage across characters: distribution by skill name and by support gem, average
DPS, and a DPS distribution histogram.

### Defensive stats (`defenseDistribution`)

Character survivability distributions: histograms for life, energy shield, armour, and evasion,
plus average life and energy shield.

## Tech stack

| Layer        | Choice                                        |
| ------------ | --------------------------------------------- |
| Language     | TypeScript (strict, ES2022, ESM)              |
| Frontend     | React 19, Vite, Tailwind CSS                  |
| Charts       | Recharts                                      |
| Data table   | TanStack Table                                |
| GraphQL client | urql                                        |
| API          | Apollo Server 4 (Express)                     |
| Database     | DuckDB (in-process, file-backed)              |
| Codegen      | graphql-codegen (end-to-end type safety)      |

## Getting started

Requires Node.js >= 18.17.

```bash
# install dependencies
npm install

# ingest data into the local DuckDB file (expects collected JSON profiles available locally)
npm run ingest:v2

# run backend (GraphQL on :4000) and frontend (Vite on :5173) together
./run.ps1
```

Or run each process individually:

```bash
npm run backend    # Apollo GraphQL server on http://localhost:4000
npm run frontend   # Vite dev server on http://localhost:5173
```

Other useful scripts:

- `npm run build` — production build (TypeScript + Vite)
- `npm run codegen` — regenerate GraphQL types
- `npm run format` — Prettier

### Sharing a local demo

`run-localtonet.ps1` and `run-ngrok.ps1` start the app behind a tunnel for sharing. The
LocalToNet script reads its token from the `LOCALTONET_TOKEN` environment variable:

```powershell
$env:LOCALTONET_TOKEN = "<your-token>"
./run-localtonet.ps1
```
